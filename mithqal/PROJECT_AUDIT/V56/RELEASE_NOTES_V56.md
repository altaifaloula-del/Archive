# RELEASE NOTES — v56.0

الأساس: v55.0 (commit `3524a84` — نسخة مرجعية لم تُعدَّل). إصدار تصحيحي: **لا وظائف جديدة** عدا GAP-007 المسجّل سابقًا كنقص في نقطة البيع.

## سلامة البيانات المالية (P0)
- **منع الإغلاق المكرر** (GAP-002): إزالة تكرار المعرّف نفسه عند الحفظ، وحارس «فرع + يوم» على أحدث نسخة سحابية داخل الكتابة المشروطة، وفهرس تفرد على الخادم (`closing_keys`) بدفعة ذرية يصبح إلزاميًا عند رفع الحد الأدنى للإصدار إلى v56.0.
- **إقفال الفترات على الخادم** (GAP-003): قواعد الإغلاقات تفرض `fin_periods/locks` (حتى على المدير)؛ وكان القفل لا يُنسخ للخادم أصلًا في التشغيل الافتراضي — صار يُنسخ دائمًا مع السجلات المستقلة، ويطابقه مدير النظام عند الدخول.
- **إقفال عدة سنوات مالية**: إقفال 2026 لم يعد مستحيلًا بعد قفل 2025، وقيد إقفال 2025 يبقى كما هو.

## عالية (P1)
- **مفتاح ZATCA** (BUG-012): لا يُولَّد تلقائيًا في Render؛ بصمة المفتاح في كل حزمة مشفّرة وفحص إقلاع (`ZATCA_KEY_ID`).
- **الرواتب حسب مدة الخدمة**: لا راتب قبل التعيين ولا بعد انتهاء الخدمة، والشهر الجزئي بنسبة الأيام ÷ 30.
- **CI**: بوابة النشر تشغّل `npm test` كاملًا (كانت 3 ملفات)، وفحص الاعتماديات التشغيلية صار مانعًا.

## متوسطة ومنخفضة

2. **قواعد Firestore** تُنشر تلقائيًا عند الدمج في `main` (`firestore-rules.yml` بعد نجاح `test:rules`). قاعدة الإقفال للإغلاقات تسري فور وجود `fin_periods/locks` — يُنشئه أول دخول لمدير النظام بعد التحديث.

4. نسبة الراتب الجزئي تغيّر أرقام مسير أي شهر فيه تعيين أو انتهاء خدمة — راجع مسير الشهر الجاري بعد التحديث.
