# SYSTEM_ARCHITECTURE — معمارية منظومة «لقمة وقيمة»

**الإصدار:** 0.1 (مسودة للاعتماد) · **التاريخ:** 2026-11-20 · **المرحلة:** 3
**المتطلبات:** ARC-01..12، وDB-01..15، وSEC-01..13، وINT-01..10، وGOV-08، وPRJ-04
**القاعدة:** كل قرار في §9 (ADR) **مقترح** ولا يُعتمد دون موافقة المالك (ARC-12).

## 1. الصورة العامة

```
 عملاء (iOS/Android)   مندوبون (iOS/Android)   نقاط البيع (فرع)   شاشة المطبخ   لوحة الإدارة (ويب)
        │                     │                      │                │               │
        └──────────── HTTPS / TLS ─────────── بوابة API واحدة ────────┴───────────────┘
                                         │
                       ┌─────────────────┴─────────────────┐
                       │  الخادم: NestJS — Modular Monolith │
                       │  وحدات معزولة + أحداث داخلية       │
                       └──┬──────────┬──────────┬──────────┘
                          │          │          │
                   PostgreSQL     Redis     Object Storage
                (المصدر الوحيد   (تخزين     (الصور، الفواتير
                  للبيانات)      مؤقت،      PDF، المرفقات)
                                 طوابير)
                          │
              طبقة التكامل (INT-01): الدفع · الرسائل · «فاتورة» · التوصيل · المحاسبة الخارجية
```

**المبدأ:**
- **نظام واحد ومصدر بيانات واحد.**
- **كل منطق العمل في الخادم.** الواجهات تعرض وتجمع المدخلات فقط (ARC-01، APP-18).
- **النظام الداخلي يعمل كاملاً دون أي تكامل خارجي** (INT-01).

## 4. أنماط إلزامية لسلامة المال والمخزون

### 4.1 القيود المحاسبية من مصدرها (ACC-18، ACC-22)

**كل عملية** (بيع، شراء، مرتجع، هدر، توصيل، ولاء) تُنشئ في **المعاملة نفسها** ثلاثة أشياء:
1. سجل العملية.
2. حدثاً في جدول «صندوق الأحداث» (Outbox).

ثم تقرأ وحدة المحاسبة الحدث وتُنشئ القيد مربوطاً بمصدره، **مرة واحدة فقط**: مفتاح فريد على (نوع المصدر، رقم المصدر، نوع القيد) (ACC-19).

### 4.2 توازن القيود وعدم تعديل المرحّل (ACC-16، ACC-17، AC-05)

- مجموع المدين = مجموع الدائن بالهللة، **ويُفرض على مستوى قاعدة البيانات** بقيد مؤجل يُفحص عند الإيداع، لا في الكود وحده.
- القيد المرحّل لا يُعدَّل ولا يُحذف: صلاحيات قاعدة البيانات تمنع ذلك، ومشغّل يرفضه (DB-10). التصحيح بقيد عكسي فقط.

### 4.3 الحجز الذري للمكونات (INV-11، AC-01)

- إنشاء الطلب (من أي قناة) يحجز المواد الخام حسب الوصفة والخيارات في معاملة واحدة.
- يمنع البيع المزدوج قفل الصف (`SELECT … FOR UPDATE`) مع شرط «الرصيد المتاح ≥ المطلوب».
- إذا لم يكفِ مكوّن يُرفض الطلب، وتُوقَف الوجبة آلياً (MNU-05).
- مهلة الحجز حسب OI-09.

### 4.4 منع التكرار (POS-13، AC-03)

- كل طلب إنشاء يحمل **مفتاح عدم تكرار** من العميل أو نقطة البيع.
- الخادم يحفظ المفتاح ونتيجته؛ الطلب المكرر يعيد النتيجة نفسها ولا ينشئ فاتورة ثانية.

### 4.5 الترقيم المتسلسل (DB-06)

- أرقام المستندات من عدّاد لكل نوع وفرع وسنة، داخل معاملة المستند نفسها.
- لا فجوات إلا بإلغاء موثق.
- عدّاد «فاتورة» (ICV) والتجزئة السابقة (PIH) يُحفظان مع الفاتورة (DB-15).

### 4.6 المال والوقت

- **المبالغ:** `NUMERIC(14,2)` بالريال، أو بدقة 4 منازل للتكلفة. لا أعداد عشرية تقريبية أبداً.
- **التقريب:** حسب OI-23.
- **الوقت:** `timestamptz` بتوقيت UTC، ويُعرض بتوقيت الرياض (DB-07).

## 5. نقاط البيع دون اتصال (POS-11، POS-12)

1. نقطة البيع تحتفظ بنسخة محلية من القائمة والأسعار والإعدادات، وتُحدَّث عند الاتصال.
2. دون اتصال: تُسجَّل العمليات المسموحة فقط (OI-20) محلياً، بمفتاح عدم تكرار وترقيم محلي مؤقت.
3. عند عودة الاتصال: ترسل الطابور بالترتيب.
   - الخادم يقبل كل عملية مرة واحدة، ويمنحها الرقم الرسمي.
   - يسجّل أي تعارض في المخزون للمراجعة، ولا يُسقط العملية.

## 6. البيئات والنشر (ARC-09، ARC-10، TST-04)

| البيئة | الغرض | البيانات |
|---|---|---|
| تطوير | جهاز المطور وحاويات Docker | بيانات تجريبية مولّدة |
| اختبار | فحص كل تغيير ومراجعة المالك | بيانات تجريبية؛ لا بيانات عملاء حقيقية |
| إنتاج | التشغيل | بيانات حقيقية فقط (GOV-03)؛ مفاتيح منفصلة |

**مسار CI/CD (GitHub Actions في منظمة الشركة):**
1. فحص الأنواع والتنسيق.
2. الاختبارات.
3. `check_brand.py`.
4. توليد OpenAPI.
5. بناء الحاويات.
6. النشر الآلي إلى بيئة الاختبار.
7. النشر إلى الإنتاج **يدوي بموافقة**.

## 7. المراقبة والنسخ الاحتياطي (ARC-11، DB-11..13، SEC-13)

- **السجلات:** منظمة (JSON) برقم تتبع لكل طلب. **لا تُسجَّل بيانات شخصية ولا أسرار.**
- **المقاييس والتنبيهات:**
  - زمن الاستجابة.
  - الأخطاء.
  - طابور الأحداث المتأخر.
  - فشل التكاملات.
  - المساحة.
- **النسخ الاحتياطي لقاعدة البيانات:**
  - يومي كامل، مع سجل المعاملات للاستعادة إلى لحظة محددة.
  - مشفّر، في موقع منفصل.
  - اختبار استعادة دوري موثق (AC-14).

## 8. الأمان (SEC)

- **الاتصال:** TLS في كل الاتصالات.
- **الجلسات:** قصيرة العمر مع تجديد. MFA للحسابات الحساسة من م3 (SEC-04).
- **الصلاحيات:**
  - تُفحص في الخادم لكل عملية، وفق مصفوفة الأدوار × الصلاحيات (AC-13).
  - الواجهة تخفي ما لا يُسمح به فقط، ولا تعتمد عليه.
- **الحماية:** تحديد معدل الطلبات، والتحقق من كل المدخلات بمخططات مشتركة (`packages/shared`)، ورؤوس أمان.
- **الأسرار:** في مدير أسرار السحابة، لا في المستودع (SEC-10).
- **الدفع:** عبر بوابة مرخصة؛ لا نخزن بيانات البطاقات (SEC-11).
