# EXECUTION_PLAN — خطة التنفيذ التفصيلية

الترتيب هو المعتمد في الأمر التنفيذي (§18). لا تبدأ مرحلة قبل عبور بوابة المرحلة السابقة (ACCEPTANCE_CRITERIA §ب). أعداد المتطلبات مأخوذة من MASTER_REQUIREMENTS.

## البنية المقترحة للمستودع (تُعتمد في م3)

```
luqma-qeema/
├─ apps/
│  ├─ api/        NestJS — الخادم والوحدات (Modular Monolith)
│  ├─ admin/      Next.js — لوحة الإدارة ERP
│  ├─ pos/        نقاط البيع (التقنية معلقة على OI-10)
│  └─ mobile/     Flutter — تطبيق العملاء
├─ packages/
│  ├─ design-tokens/  مصدر واحد للألوان والخطوط يُصدَّر لـ CSS وDart
│  ├─ ui/             مكونات الويب المشتركة
│  └─ shared/         أنواع ومخططات تحقق مشتركة
├─ brand/         الهوية المركزية بالهيكل الإلزامي (أمر الهوية §11)
├─ infra/         Docker وCI/CD والمراقبة والنسخ الاحتياطي
├─ tests/         E2E وأداء وأمن
├─ scripts/
└─ docs/
```

## ما يمكن البدء به فور اعتماد المرحلة 1

- **م2 (الهوية)** يمكن تنفيذها بالكامل في بيئة العمل الحالية، وأبدأ بعرض اتجاهات الشعار ولوحة الألوان المقترحة للاختيار.
- **م3** تحتاج حسم OI-21 (بيئة البناء) وOI-06 (ملكية المستودع) قبل كتابة الشيفرة. أما تصميم مخطط قاعدة البيانات ووثيقة المعمارية فيمكن البدء بهما بالتوازي كوثائق.
