# تقرير الفحص الأولي لحالة المشروع — «لقمة وقيمة»

**التاريخ:** 2026-11-20 · **المرحلة:** 1 (التحليل والتوثيق) · **الحالة:** مسودة بانتظار الاعتماد

## 1. ما تم فحصه

| البند | النتيجة |
|---|---|
| مساحة العمل الحالية | فارغة؛ لا شيفرة ولا وثائق سابقة للمشروع |
| مستودعات GitHub المتاحة للجلسة | 4 مستودعات (daily، Archive، exam، albaroon)؛ لا يوجد بينها مستودع باسم «لقمة وقيمة» أو بمحتوى مطابق ظاهرياً |
| ملف الأمر التنفيذي | مقروء بالكامل (1033 سطراً، 22 قسماً) وتم تحويله إلى 249 متطلباً مرقّماً |
| أدوات بيئة التطوير | Node 22، PostgreSQL client، Docker، Python 3 متوفرة. **Flutter غير مثبت.** تثبيت الحزم (npm/pip) **محجوب** في هذه البيئة حالياً |

**الاستنتاج:** المشروع جديد من الناحية التقنية. **لكن لا يُفترض ذلك نهائياً**: إن كانت لدى الشركة شيفرة أو تصاميم أو شعار أو بيانات أصناف في مكان آخر، فيجب تزويدنا بها قبل المرحلة 2 (انظر OI-01).

## 2. ما هو موجود

- الأمر التنفيذي (المصدر الأعلى للمتطلبات).
- لا هوية بصرية منفذة، ولا قاعدة بيانات، ولا بنية تحتية، ولا حسابات سحابية معروفة.

## 3. ما ينقص لبدء التنفيذ (معوّقات حقيقية)

1. **بيانات الكيان القانوني** (الاسم الرسمي، السجل التجاري، الرقم الضريبي) — مطلوبة قبل أي فاتورة ضريبية أو تكامل.
2. **اسم برنامج المحاسبة الحالي** وقدرته على الربط، وتحديد **النظام المرجعي للدفاتر الرسمية**.
3. **الميزانية** — كل خدمة مدفوعة (استضافة، رسائل OTP، بوابة دفع، حسابات المتاجر، الربط مع «فاتورة») تحتاج موافقة.
4. **ملكية الحسابات**: حساب GitHub المتاح حالياً شخصي؛ والمتطلب GOV-08 يشترط ملكية الشركة ← يُقترح إنشاء منظمة GitHub باسم الشركة.
5. **بيئة البناء**: تثبيت الحزم محجوب هنا، وFlutter غير متوفر. يمكن إكمال الوثائق والتصميم وتصميم قاعدة البيانات في هذه البيئة، أما بناء التطبيقات وتشغيلها فيتطلب تفعيل الوصول للشبكة أو العمل من Claude Code على مستودع الشركة.
6. **قرارات تشغيلية** (طريقة تقييم المخزون، سياسة الحجز، الأجهزة، وسائل الدفع، مناطق التوصيل ورسومه...) — مفصلة في OPEN_ISSUES.

## 4. تقييم واقعي للنطاق

المطلوب منظومة تجارية متكاملة بحجم ERP + POS + تطبيقين + محاسبة مزدوجة القيد + تكاملات نظامية. هذا عمل يمتد عادة **عدة أشهر لفريق**، وسيُنفَّذ هنا على جلسات متتابعة بمراحل معتمدة. للشفافية، هذه أمور لا أستطيع إنجازها بنفسي وتحتاج إلى الشركة أو إلى طرف مرخّص:

- التحقق القانوني وإصدار التراخيص.
- فتح الحسابات السحابية وحسابات Apple وGoogle وبوابة الدفع ومزود الرسائل باسم الشركة.
- تسجيل الأجهزة في منظومة «فاتورة» والحصول على شهادات الربط.
- الطباعة والتنفيذ المادي للهوية.
- شراء الأجهزة: نقاط البيع، والطابعات، والموازين، والقارئات.
- المراجعة المهنية للامتثال من محامٍ ومحاسب قانوني.

## 5. ملاحظة معمارية جوهرية (تحتاج اعتماداً — OI-12)

ترتيب المراحل المعتمد يضع المحاسبة (م7) بعد المخزون (م4) والمشتريات (م5) ونقاط البيع (م6)، مع أن هذه الوحدات **تولّد قيوداً**. ولتحقيق شرط «ممنوع إنشاء وظائف مالية غير مترابطة مع العمليات الأصلية» (قاعدة 9)، يُقترح بناء **نواة الأستاذ العام** في المرحلة 3 ضمن البنية الأساسية: دليل الحسابات، والقيد المتوازن، ومنع التعديل بعد الترحيل، وربط القيد بمصدره. ثم تُستكمل وحدة المحاسبة كاملة في م7. ولا يغيّر هذا ترتيب المراحل، وإنما يحدد مكان الأساس.

وبالمنطق نفسه تُبنى **نواة الطلبات** مع التطبيق في م8، وتُستكمل دورة التوصيل في م9.
